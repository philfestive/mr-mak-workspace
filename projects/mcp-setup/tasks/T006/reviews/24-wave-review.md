## Accepted roadmap requirements

1. **Sequence by dependency.** Freeze the selected client/account/project matrix
   and registry contract before generating templates. Resolve a common launch
   context before wiring account selection, inspector, history and resume.
   Implement offline validation before active configuration changes. Perform one
   selected native-session pilot before broader rollout. Each package names
   its prerequisites, release condition, reviewer and next owner; parallel
   packages have disjoint files. Client-adapter work can overlap only after its
   shared interface is fixed.

2. **Make ownership concrete.** Give every package an outcome, exact working
   folder, allowed paths and prohibited operations. One writer owns shared
   application interfaces, registry/schema, Workspace metadata and consolidation.
   Re-read those files before editing. External projects retain their own rules,
   boards and runtime owners. Unassigned owners remain unresolved; temporary
   lane numbers must not become permanent accounts or a standing agent roster.

3. **Preserve running work.** Distinguish checkout revision, packaged build,
   installed payload and actual running service. Source tests cannot prove an
   installed service loaded the changes. Prepare updates while sessions continue;
   any application restart needs the owner's permission. Name active sessions
   and runtime owners to preserve without recording transcripts or credentials.
   Never terminate another agent to apply configuration or refresh tools.

4. **Prove account separation.** A selected context must reach launch,
   inspection, history and resume consistently. Use two synthetic homes and two
   project roots to check that selection does not cross accounts. Preserve the
   default route until selection. Native sign-in stays in each native store;
   do not copy auth files. Explicitly resolve required environment-variable names
   and trust/precedence. A role profile and a separate configuration home are
   distinct concepts.

5. **Respect machine Git gates.** Reuse lane 17's dated evidence; do not invent
   another measurement or fetch to measure. No planning wave stages, commits,
   pushes, cleanup or repository moves. A future commit requires an explicit
   request, exact paths and passing scoped cached whitespace checks. Every Git
   write disables automatic maintenance. Push requires the named repo/branch or
   applicable D1 grant, fresh read-only origin evidence, and never main/force.
   Worktree proposals must obey the allowed path and named-branch rules.

6. **Version each actual client contract.** Avoid one generic MCP JSON export.
   Account for Codex TOML/trust/profile layers, Claude Code versus Desktop,
   Cursor interpolation, Kimi distribution and OpenCode major version. Pin the
   selected runtime/package/plugin source with update ownership and revalidation
   triggers. A cache's highest version is not authoritative installation evidence.
   Unsupported adapters stay visible as unsupported.

7. **Keep evidence scoped and secret-free.** Separate desired, configured,
   enabled, locally prepared, exposed, connected, authenticated, project-bound
   and consumer-verified states. Unknown, failed, stale and not-applicable need
   explicit meanings. Inspector handshakes cannot establish native chat readiness.
   Bind receipts to client/version, account alias, home, project, source and time;
   invalidate them after relevant changes. No raw env, headers, arguments, login
   stores, error bodies or private job receipts enter Git or reports.

8. **Keep Godot and budgets bounded.** One named runtime owner serializes the
   machine's one Godot process. Observer, artifact and runtime-writer authority
   remain separate and require exact project/session binding. Do not infer a
   qualified Codex gateway from a skills-only plugin or Claude packaging.
   Future installation, login, paid generation and runtime work require their
   own selected scope. The current request's 12 additional planners establish
   neither a generation budget nor authorization to execute future waves.
