# GDD preparation

This is the GDD workflow guide. The selected game's actual GDD will live in its
owning project; [Build focus](#/team-hub/6) records its route and accepted revision.

## Before writing the design

Choose the project and exact source home. Read existing decisions and relevant
retained examples. Ask focused questions until purpose, experience, core loop
and selected scope are clear. Keep exclusions and unresolved choices visible.

Use the existing project and GDD templates in
`projects/workspace-organization/templates/` when a suitable source is absent.
These are templates, not an approved game. The
[output standard](#/workspace-organization/5) describes the source and proof
contract. A GDD defines intended behavior; result records hold measured behavior.

## Next step

Define the source index and schemas for the accepted scope, then select a bounded
first slice. Keep the owning GDD and schema routes visible in Build focus.
