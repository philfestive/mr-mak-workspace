# MCP setup and delivery waves

The owner selected **shared core tools plus tools matched to each project or
role**. The existing setup is distributed across clients, account homes and
projects. Keep those configurations in their owning locations and give future
agents one clear index and startup process.

This report combines a 12-agent setup review with a second 12-agent planning
wave requested for setup, version control and best practices. These are
temporary assignments assisting a solo developer.

## What the review establishes

- Empty project MCP files do not erase inherited user configuration. A chat's
  effective tools depend on its actual client, account home and working folder.
- The local account wrappers select separate homes. The desktop launcher source
  does not select those wrappers, and its MCP inspector scans service/Workspace
  context. Running application behavior still needs a scoped verification.
- Godot projects require separate bindings and runtime owners. Cached skills or
  plugin files do not establish a live connection.
- Existing fal templates use an older authentication route. New setup packets
  must reconcile current provider guidance before activation.

Use [Inventory](inventory.md) for the observed setup, [Setup plan](setup-plan.md)
for the target architecture, and [Delivery waves](waves.md) for the implementation
sequence. [Staffing and accuracy](staffing.md) assigns 30 bounded implementation
roles across those waves. [Agent startup](agent-startup.md) gives future agents a reusable brief.
[Reviews](reviews.md) links the retained evidence and independent review.

The review prepares an implementation plan. It does not claim all MCPs are
connected, authenticated or ready for use. No active MCP configuration, login,
installation, paid job, application restart, commit or push was performed.
