# Agent startup and resume

Use this brief for a bounded task. Read current sources when resuming; old
review reports explain evidence from their observation date, not current
runtime state. The owner is a solo developer assisted by the assigned agents.

## Paste-ready startup brief

```text
Task/result:
Working repository and exact absolute folder:
Rules, project brief and authoritative task board:
Owner/reviewer and single writer for shared files:
Allowed edit paths and authorized operations:
Client/executable/version:
Account alias and resolved configuration home:
Role/profile and required connection IDs:
Model/effort/permissions/budget: preserve current choices; name unknowns
Configuration sources/trust/overrides:
Tools exposed in this session and dated validation evidence:
Existing apps/runtimes/sessions to preserve:
Baseline revision/file state and previous handoff:
Acceptance checks and next dependency:
Owned output/handoff path:
```

A numbered account folder does not establish login identity. Record aliases
without emails or tokens. Use the same account/project context for launch,
inspection, history and resume; treat legacy session identity as unresolved
until established.

## Readiness for this task

| Stage | Evidence required |
| --- | --- |
| Discovered | Exact client/home/project source and observation date |
| Declared/enabled | Effective layers, trust/approval and selected plugin version |
| Locally prepared | Valid endpoint/runtime/cwd/files and required variable names present |
| Connected/authenticated | Current intended native client/account connection; auth where required |
| Correctly bound | Server/project/resource identity matches the task |
| Capability authorized | Required capabilities exposed and intended use allowed |

Record pass, fail, unknown or justified not-applicable for each stage. An
inspector's separate handshake is evidence for that inspector context. A
resources-only server need not expose tools. Tool advertisement itself does not
authorize a call.

## During work

Keep one owner per file/index. For another repository, read its actual rules and
use its local board; link its sources here. Runtime work belongs to the named
operator. Godot uses the machine's single process and selected project binding.
Creative jobs use the selected provider/account/route and approved budget;
retain private job IDs and resume existing jobs after timeouts.

Requalify after changes to client, home, account, project, profile, plugin,
executable, auth or connection session. Preserve deliberate disabled routes.
Report missing prerequisites without claiming that the rest of the machine is
broken. The [version-control workflow](version-control.md) governs any later
checkpoint, commit or push.

## Handoff

```text
Task/owner/date and status:
Source revision and exact owned changes:
Selected proposal versus implemented behavior:
Checks actually run, results and linked evidence:
Native connection/binding context and freshness:
Known limits, unverified steps and decisions:
Apps/runtimes/leases left running and their owner:
Next action, exact allowed scope and receiving owner:
```

Keep auth files, raw logs, transcripts, environment values and private receipts
out of tracked reports. The onboarding process is at
[processes/mcp-agent-onboarding.md](../../processes/mcp-agent-onboarding.md).
