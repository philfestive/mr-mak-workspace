## Concrete gaps

1. **Godot design drift.** PRODUCT_DEFINITION identifies itself as Current and
   describes Western chickens. AI_START_HERE and Docs/README describe the newer
   accepted Classic-first direction. The project owner should reconcile the
   owning product reference and its routes before it supplies a new GDD here.
   Do not resolve this by writing a third, competing product definition.
2. **Godot decision drift.** AGENTS describes D-CNT-RACE-FARM-SCHEMA as Accepted;
   AI_START_HERE and the decision registry identify it as Superseded by
   D-CNT-RACE-FARM-CURRENT-INPUTS. The successor still has a bounded prospective
   binding/proof-pending scope. Current design or implementation requires its
   owning decision/queue checks, not the predecessor's status line.
3. **Shader project versus working directory.** Its INDEX and TEAM explicitly
   distinguish the saved project, SHD-00's historical C: directory and active
   E: research. Use exact working folders in briefs; cosmetic naming cannot
   qualify a different directory or tool binding.
4. **Workspace entry drift during active editing.** The registry advertised
   Projects/Notes tabs, initially holding roster/handoff content. Those files
   later became agents.md/handoffs.md while the registry still referenced the
   other names when checked. Treat this as an integration check for the existing
   writer, not proof that the final hub will remain broken.
5. **No selected personal GDD here.** Existing sample cards and the template
   goals file do not define the first real project. First select the project and
   current accepted design source, then register its canonical route.
6. **Historical inventory is not a fresh census.** `C:/Dev/_index/PROJECTS.md`
   explicitly dates its generated inventory to September 18. Its numbers and
   activity signals were not reused as current machine facts in this review.

## Naming recommendation

Keep the established SHD, AUD, BF-CX, RGS and COMFY identifiers. The screenshot's
`prefix-ID - Domain | Responsibility` structure is readable and useful; a lane
ID is not its task ID or a universal priority. Preserve spelling and physical
paths that already identify projects, sources and evidence.

This workspace needs readable project/output cards, an exact source route, and
one current writer for shared metadata. It does not need a persistent chat or
folder for every model, asset, review wave or hypothetical role. New local
projects can use stable descriptive IDs and the [project template](../../projects/workspace-organization/templates/project.md).
