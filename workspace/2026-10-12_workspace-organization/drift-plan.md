# Preventing drift without losing clear goals

This is a proposed operating aid for the owner's current refinement direction,
not a hard admission rule for product material. It uses existing sources and
indexes. [Macro goals](macro-goals.md) give the outcomes; the
[design-direction source](../../projects/workspace-organization/design-direction.md)
owns the current questions and answers.

## The changes to watch

| Change | Response |
| --- | --- |
| Owner changes a design answer | Update its owning answer/decision and identify the affected requirements |
| Source or schema changes | Recheck the dependent contract/output; retain unaffected evidence |
| Example points to a different run/revision | Correct the identity and ask whether the illustrated property still holds |
| Runtime/device/renderer differs | Limit the earlier claim; do not extend a desktop result to a phone |
| A later decision supersedes a frozen record | Link the successor while preserving the original record |
| A card/path or shared owner changes | Reconcile its existing routes with the actual current writer |

## A small source-linked loop

1. State the macro goal and exact question this work serves.
2. Read the current owning answer/source; identify version, subject and limits.
3. Assign one writer to the exact files. Parallel reviewers inspect distinct
   questions and return findings to that writer.
4. Save the useful output or explicit answer in its owning home and read it back.
5. Update dependent indexes and review only claims affected by the change.

A short record can contain source/run, illustrated property, owner reaction,
uncertainty and next question. [Examples](examples.md) use that shape. Keep
candidate, preferred example, accepted design and measured behavior distinct.
Do not create a new status register for every review or copied source.
